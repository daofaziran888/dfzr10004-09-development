# 智能采集质量管控平台

面向数据采集团队的质量管控与效率优化平台。覆盖采集任务编排、抓取结果校验、采集链路监控、数据格式转换、去重比对、异常重试、采集审计与合规管理的完整采集质控链路。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 去重预演

采集去重比对模块在策略维护之外提供预演能力（`backend/app/services/dedup.py` 的
`DedupRehearsalService`，页面在「采集去重比对管理」下方）：

- `POST /api/dedup/rehearsals`：按策略编号、时间窗口与比对字段计算重复组，
  按排序字段与保留策略给出拟保留记录，被排除记录附裁决依据；空窗口会明确说明
  没有可比记录；排序值相同（相似度相同）时保留先到达的记录。
- `GET /api/dedup/rehearsals`、`GET /api/dedup/rehearsals/{id}`：批次列表与详情。
- `POST /api/dedup/rehearsals/{id}/adjudicate`：一次提交人工裁决，支持按重复组
  批量处理、只处理其中一条或整组回执；人工裁定具有最高优先级，结论回写同一
  去重批次并写入裁定档案，后续预演不会被策略结果覆盖。
- `GET /api/dedup/rehearsals/{id}/summary`：拟保留记录、待复核组与已排除数量汇总，
  并与采集数据标注待办核对一致性。

联动规则：高风险或相似度落在阈值边界区间（±0.05）的组会写入采集数据标注的
待复核清单（如 DEDU-0002 窗口内的 SKU-1002 组关联 TAG-0002），复核结论同步更新
标注待办。同一业务键的回执再次送达时只生成一个去重组；两个批次并发提交同一
业务键时先到者生效，组仍按各自时间窗口隔离。
